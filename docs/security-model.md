# Security and Privacy Model

## Deployment status

The code and dependencies are unaudited research software. No production deployment or real funds are supported. Mock-proof networks omit the zero-knowledge relation and allow forged payments. Default node binaries reject those networks; explicit development builds are required.

## Observers

| Observer | Information available |
|---|---|
| Chain reader | Block heights and times, fixed-shape slots, nullifiers, commitments, ciphertexts, public issuance and fund payouts |
| Peer or relay | Transaction arrival times, leaf statements and fee openings, transport peers |
| Producer | Relayed data, selected transactions, private aggregation witnesses and its own padding |
| Recipient | Recovered note plaintexts and the inclusion heights of its payments |
| Local privileged process | Files and memory allowed by its OS identity; potentially wallet and fund secrets |

Fixed block capacity obscures a direct public paid-slot count. It does not hide slot inclusion, eliminate traffic analysis or prevent a known payment from being linked to a block. Padding generated by an adversarial producer does not provide unknown cover traffic against that producer. Low traffic and active probing weaken practical privacy.

## Cryptographic boundaries

The current KoalaBear degree-four proof configuration has a nominal query/grinding score of 100; complete instance-specific conjectured and Johnson bounds are lower. It is not a reviewed quantum-sound configuration. ML-KEM output encryption and ML-DSA signatures do not make the full protocol post-quantum: proof soundness, hashing, transport and implementation security require separate analysis.

Ciphertext correctness is outside the slot relation. The root binds the ciphertext digest but does not establish decryptability. Leaf fee openings are visible to relays and producers. Zero-knowledge randomness must remain fresh and must never be restored or reused.

The additive accumulator relies on canonical encodings, fixed tree shape, bounded multiplicity, child-key pinning and native duplicate rejection. The algebraic sum is not a substitute for any of those rules.

## Network and consensus limits

Direct flooding has no implemented Dandelion++ source-hiding layer. Transport uses Noise rather than a post-quantum handshake. The local reorganization bound can prevent nodes separated by a long partition from converging automatically. Anti-spam constants require deployment measurements. Fixed capacity has no implemented demand-based automatic adjustment, and variable fee bids are not active.

The root circuit's 30-bit height decomposition also bounds the supported height including reward maturity. Proof-size limits, concurrent-proving memory, verification cost and long-running storage growth require deployment-specific validation. The current node retains full chain data and does not implement pruning.

## Custody and recovery limits

Encrypted keystores, explicit unlocking and zeroizing owned buffers reduce specific exposure paths. They do not establish complete erasure of compiler copies, allocator remnants, swap, crash dumps, traces or dependency work buffers. A compromised node process or OS administrator can access active secrets.

RPC read capability is not cryptographic watch-only recovery. Historical completeness, independently current checkpoints and durable order records remain prerequisites for safe recovery. Timeout does not cancel a submission. Restoring stale state must not create a new payment ID for an unknown outcome.

## Production restrictions

Independent cryptographic review, adversarial network testing, resource limits, cross-platform custody checks, measured recovery procedures, a compatible quantum-sound suite and explicit activation specifications are required before a production release can be considered. Passing repository CI establishes regression results for the tested configuration only.

The legacy query/grinding score does not establish composite security. The
selected launch requirements and planned D8 suite are specified in the
[security review scope](proof-security-review.md); D4/W16 is not a qualifying
post-quantum suite.
